# Code of Conduct

[Português (Brasil)](../Translations/Portugues-Brasil/Governance/CODE_OF_CONDUCT.md) · [Español (Latinoamérica)](../Translations/Espanol-LATAM/Governance/CODE_OF_CONDUCT.md)

Cosmeron is built around curiosity, learning, readability, and collaboration. Participation in the project should reflect those same values.

## Expected conduct

When participating in Cosmeron, contributors and maintainers are expected to:

- treat other people with respect, regardless of experience level or background;
- discuss ideas, code, and technical decisions without personal attacks;
- give criticism that is specific, constructive, and useful;
- accept good-faith disagreement without turning technical discussion into hostility;
- help newcomers understand the project rather than treating unfamiliarity as incompetence;
- respect authorship, attribution, licensing, and the work of other contributors;
- avoid harassment, intimidation, discrimination, threats, doxxing, or deliberate disruption;
- avoid publishing another person's private information without clear permission.

Strong technical disagreement is welcome. Disrespect is not.

## Scope

This Code of Conduct applies to project spaces and project-related interactions, including:

- issues and pull requests;
- discussions and code review;
- commits and contribution messages;
- documentation and community spaces officially associated with Cosmeron.

It also applies when someone is publicly representing the project.

## Enforcement

Maintainers may edit or remove comments, reject contributions, close discussions, temporarily restrict participation, or permanently ban participation when behavior materially violates this Code of Conduct.

Enforcement should be proportionate to the conduct, its severity, its repetition, and its effect on the community.

Whenever practical, maintainers should distinguish between a correctable mistake and deliberate or repeated harmful behavior.

## Reporting

Do not publish sensitive personal information in a public report.

For conduct issues that can safely be discussed publicly, open a repository issue and clearly identify it as a conduct concern.

For sensitive conduct incidents, use GitHub's platform reporting and moderation mechanisms rather than posting confidential details publicly. A dedicated private conduct-reporting channel may be added as the project grows.

Security vulnerabilities should be reported through the procedure described in [SECURITY.md](SECURITY.md), not through the conduct process.

## Project principle

    Be curious.
    Be precise.
    Be respectful.
    Help others understand.

This Code of Conduct may evolve as the community grows.
