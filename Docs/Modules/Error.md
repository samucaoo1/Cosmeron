# Error

The **Error** module provides two complementary mechanisms for reporting failures in Cosmeron: **Status** for recoverable errors and **Panic** for unrecoverable conditions.

A function can return an `OPSTATUS` to let its caller decide how to handle an error. When an invariant is violated or execution cannot safely continue, `PANIC` and `PANIC_ASSERT` report the failure location and terminate the process.

The module does not require a global *last-error* variable.

```c
#include "Cosmeron/Core/Error/Status.h"
#include "Cosmeron/Core/Error/Panic.h"
```

---

# Overview

| Package | Interface | Purpose | Execution continues |
| --- | --- | --- | --- |
| Status | `OPSTATUS`, `STATUS_CONST(...)` | Reports normal success and recoverable errors | Yes |
| Panic | `PANIC(message)` | Reports a critical failure and aborts | No |
| Panic | `PANIC_ASSERT(condition)` | Aborts if a required condition is false | Only if the condition is true |

The Status API follows the library's configurable namespacing scheme.

### Macro form

```c
OPSTATUS status = STATUS_CONST(SUCCESS);
```

### Direct form

```c
OPSTATUS status = STATUS_SUCCESS;
```

These two expressions refer to the same enum constant when the default namespace is used.

To configure namespacing, define the namespace macros **before** including the header:

```c
#define COSMERON_NAMESPACE MyProject
#define COSMERON_NAMESPACE_CONST MYPROJECT

#include "Cosmeron/Core/Error/Status.h"
```

The direct constant becomes `MYPROJECT_STATUS_SUCCESS`, while the macro form stays unchanged:

```c
OPSTATUS status = STATUS_CONST(SUCCESS);
```

Unlike Status constants, **`PANIC` and `PANIC_ASSERT` are themselves public macros**. Their underlying functions are internal implementation details, not alternate public entry points.

---

# API reference

## Interface summary

| Interface | Description | Terminates process |
| --- | --- | --- |
| [`OPSTATUS`](#opstatus) | Public status-result type | No |
| [`STATUS_CONST`](#status_const) | Accesses a status constant using the configured namespace | No |
| [`STATUS_TABLE`](#status_table) | X-macro listing all predefined status codes and messages | No |
| [`PANIC`](#panic) | Prints a diagnostic and aborts | Yes |
| [`PANIC_ASSERT`](#panic_assert) | Checks an assertion and aborts if it fails | On failure |

# Status

`Status.h` declares an enumeration of operational outcomes. Use it for expected, recoverable failure conditions rather than terminating the process.

A function with a fallible operation and no primary return value can return `OPSTATUS` directly. A fallible function with a separate result should generally return `OPSTATUS` and write the result to an output parameter only on success.

---

# OPSTATUS

The standard return type for an operation that can fail.

### Syntax

#### Macro / public alias

```c
OPSTATUS status;
```

#### Direct enum tag

```c
enum Status_Status status;
```

`Status_Status` above is the default-namespaced **enum tag**, not a separate typedef. `OPSTATUS` is the preferred public type alias and does not depend on the custom namespace spelling.

---

### Values

The module currently defines **18** status constants.

| Constant | Description |
| --- | --- |
| `SUCCESS` | Operation completed successfully |
| `GENERIC_ERROR` | Error not represented by a more specific status |
| `INVALID_ARGUMENT` | Invalid argument supplied |
| `OUT_OF_RANGE` | Value or index outside the allowed range |
| `OUT_OF_MEMORY` | Required memory could not be obtained |
| `NOT_FOUND` | Requested value or resource was not found |
| `ALREADY_EXISTS` | Value or resource already exists |
| `NOT_SUPPORTED` | Requested operation is not supported |
| `NOT_AVAILABLE` | Required resource or operation is unavailable |
| `BUSY` | Resource is busy |
| `WOULD_BLOCK` | Operation would block |
| `TIMEOUT` | Operation exceeded a time limit |
| `CANCELLED` | Operation was cancelled |
| `ARITHMETIC_OVERFLOW` | Arithmetic result cannot be represented |
| `DIVISION_BY_ZERO` | Attempted division by zero |
| `INVALID_SEQUENCE` | Input sequence is invalid |
| `INCOMPLETE_SEQUENCE` | Input sequence is incomplete |
| `INSUFFICIENT_SPACE` | Supplied space is insufficient |

Each entry is accessed through `STATUS_CONST(NAME)`. The direct spelling under the default namespace is `STATUS_NAME`.

---

### Return value

`OPSTATUS` is a **type**, not a function; functions returning it use `STATUS_CONST(SUCCESS)` for success or one of the failure constants when an operation does not complete.

---

### Remarks

- An `OPSTATUS` value is not a `bool`; compare it with a named status constant.
- Codes are generated by an enum without explicit numeric assignments. Do **not** depend on particular integer values in serialized data or external protocols.
- The status itself does not automatically record a message, a stacktrace, or a global error.
- Handling and propagating an `OPSTATUS` does not terminate the process.

---

### Example

```c
static OPSTATUS CheckCapacity(size_t used, size_t capacity) {
    if (used > capacity)
        return STATUS_CONST(OUT_OF_RANGE);

    return STATUS_CONST(SUCCESS);
}

OPSTATUS status = CheckCapacity(12, 8);

if (status != STATUS_CONST(SUCCESS)) {
    /* Handle the recoverable error. */
}
```

# STATUS_CONST

Expands to the configured namespace-qualified constant associated with a status name.

### Syntax

#### Macro form

```c
STATUS_CONST(INVALID_ARGUMENT)
```

#### Direct form

```c
STATUS_INVALID_ARGUMENT
```

---

### Parameters

| Parameter | Explanation |
| --- | --- |
| `NAME` | One of the uppercase identifiers listed in the status table |

---

### Return value

Expands to an **enum constant**. It is a preprocessor naming macro and is not called at runtime.

---

### Remarks

- The direct form depends on the constant namespace configuration.
- Using the macro form avoids hard-coding a namespace into reusable code.
- The status constants should be preferred over integer literals.

---

### Example

```c
static OPSTATUS ValidatePointer(const void *pointer) {
    if (pointer == NULL)
        return STATUS_CONST(INVALID_ARGUMENT);

    return STATUS_CONST(SUCCESS);
}
```

---

# STATUS_TABLE

The X-macro providing a single source of truth for the status identifiers and their human-readable English messages.

### Syntax

#### Macro form

```c
STATUS_TABLE(X)
```

#### Direct form

There is no corresponding direct function. `STATUS_TABLE` is a **code-generation macro**, not a runtime callable.

---

### Parameters

| Parameter | Explanation |
| --- | --- |
| `X` | User-supplied macro accepting `(NAME, MESSAGE)` |

---

### Return value

None. Expands the supplied macro once per status-table entry.

---

### Remarks

- The current table contains 18 pairs of identifiers and messages.
- The enum in `Status.h` is generated from this table.
- The messages are string literals; no public `Status_ToString` function is currently declared.
- A caller may reuse the table to create mappings, switch cases, or diagnostics without duplicating its entries.

---

### Example

The following helper demonstrates deriving messages from the existing X-macro rather than manually repeating the status list.

```c
static const char *StatusMessage(OPSTATUS status) {
    switch (status) {
#define STATUS_MESSAGE_CASE(NAME, MESSAGE) \
        case STATUS_CONST(NAME): return MESSAGE;
        STATUS_TABLE(STATUS_MESSAGE_CASE)
#undef STATUS_MESSAGE_CASE
        default: return "Unknown status";
    }
}

const char *message = StatusMessage(STATUS_CONST(OUT_OF_MEMORY));
/* message points to "Out of memory" */
```

# Panic

`Panic.h` provides explicit fatal-error reporting.

Both public macros record the **source-file name**, **line number**, and **calling function** at the invocation site. They delegate to an internal routine that prints a diagnostic to `stderr`, attempts to print a stacktrace, and calls `abort()`.

A panic is appropriate for an impossible state or a contract failure that makes continued execution unsafe. Expected errors should normally return `OPSTATUS` instead.

---

# PANIC

Reports a fatal failure and terminates the process.

### Syntax

#### Macro form

```c
PANIC(message);
```

#### Direct form

`PANIC` has **no supported public direct-function form**. The backing `PANIC_INTERNAL_FUNC(Trigger)` function is an implementation detail, with additional location arguments.

---

### Parameters

| Parameter | Explanation |
| --- | --- |
| `message` | Diagnostic message passed as `const char *` |

---

### Return value

No value. The internal routine invokes `abort()` and does not return normally.

---

### Remarks

- Automatically supplies `__FILE__`, `__LINE__`, and `__func__` from the call site.
- Writes the panic report to `stderr`.
- A null message pointer is printed as `unknown` by the current implementation.
- Requests a stacktrace, subject to platform support and available symbols.
- This is not a recoverable status code.

---

### Example

```c
static void RequireInitialized(int initialized) {
    if (!initialized)
        PANIC("Subsystem must be initialized");
}
```

Example diagnostic structure (specific paths, function names, and stack frames depend on the build):

```text
============== PANIC ==============
message : Subsystem must be initialized
file    : example.c
line    : 7
function: RequireInitialized

Stacktrace:
...
===================================
```

---

# PANIC_ASSERT

Checks a required condition and triggers a panic if it evaluates to false.

### Syntax

#### Macro form

```c
PANIC_ASSERT(condition);
```

#### Direct form

There is **no supported public direct-function form**. The macro is required to stringify the expression and capture source-location information.

---

### Parameters

| Parameter | Explanation |
| --- | --- |
| `condition` | Expression tested as a C condition |

---

### Return value

None. If the condition is true, execution continues. If it is false, the macro invokes the panic handler, which calls `abort()`.

---

### Remarks

- The expression is evaluated once by the `if (!(condition))` test.
- On failure, the report contains `Assertion failed: ` followed by the original expression text.
- Unlike standard `assert`, this macro does not check `NDEBUG`; it remains active even in builds defining that macro.
- It is meant for invariants and programmer contracts, not ordinary user-input validation.
- It expands as a `do { ... } while (0)` statement and can be used in conditional blocks.

---

### Example

```c
static void UseBuffer(const void *buffer, size_t length) {
    PANIC_ASSERT(buffer != NULL || length == 0);

    /* Continue only if the invariant holds. */
}
```

When the assertion fails, the diagnostic includes:

```text
Assertion failed: buffer != NULL || length == 0
```

# Stacktrace behavior

A panic invokes an **internal** stacktrace function. It is not exposed as a separate public error-handling API.

| Platform | Current implementation |
| --- | --- |
| Windows | Captures up to 32 frames using `CaptureStackBackTrace`; prints frame addresses |
| Unix-like systems selected by `OS_UNIX` | Captures up to 32 frames using `backtrace`; uses `backtrace_symbols` for symbol strings when available, otherwise prints addresses |
| Other detected platforms | Empty stacktrace routine; the panic diagnostic is still printed and the process still aborts |

Symbol quality and portability depend on the target platform and build environment. In particular, the current Unix implementation expects `execinfo.h` and related functions to be available.

### Internal routines

| Implementation macro | Default direct symbol | Signature |
| --- | --- | --- |
| `PANIC_INTERNAL_FUNC(Trigger)` | `Panic_Internal_Trigger` | `void (const char *message, const char *file, int line, const char *function)` |
| `PANIC_INTERNAL_FUNC(Stacktrace)` | `Panic_Internal_Stacktrace` | `void (void)` |

These names describe the implementation and should **not** be used in preference to `PANIC` or `PANIC_ASSERT`.

# Choosing Status or Panic

| Situation | Appropriate mechanism |
| --- | --- |
| Invalid argument that a caller can correct | `STATUS_CONST(INVALID_ARGUMENT)` |
| Missing resource | `STATUS_CONST(NOT_FOUND)` |
| Memory allocation failure that the caller may handle | `STATUS_CONST(OUT_OF_MEMORY)` |
| Transient unavailable resource | `STATUS_CONST(NOT_AVAILABLE)` or a more specific code |
| Broken invariant where continuing is unsafe | `PANIC_ASSERT(condition)` |
| Deliberate fatal failure with an explanatory message | `PANIC("message")` |

### Example

```c
static OPSTATUS ReadValue(
    const int *values,
    size_t count,
    size_t index,
    int *outValue
) {
    if (outValue == NULL)
        return STATUS_CONST(INVALID_ARGUMENT);

    if (index >= count)
        return STATUS_CONST(OUT_OF_RANGE);

    if (values == NULL)
        return STATUS_CONST(INVALID_ARGUMENT);

    *outValue = values[index];
    return STATUS_CONST(SUCCESS);
}

int items[] = {10, 20, 30};
int value = 0;

OPSTATUS status = ReadValue(items, 3, 1, &value);

if (status == STATUS_CONST(SUCCESS)) {
    /* value == 20 */
} else {
    /* Decide how to handle the failure. */
}
```

A fallible function should leave its required output unchanged on failure unless it explicitly documents another contract.

---

# Notes

- **Error is a Core module**. The documented paths refer to `Core/Error`, not the separate `Modules/Network/Error` package.
- **Status** is declared in `Status.h`; **Panic** is declared in `Panic.h`.
- `OPSTATUS` and the public panic macros remain convenient short spellings. Other generated names follow the configured namespace.
- Status messages are defined in `STATUS_TABLE`; they are not automatically printed when a function returns an `OPSTATUS`.
- Panics print diagnostics and terminate through `abort()`; they do not return `OPSTATUS`.
- Recoverable errors should be propagated explicitly by callers instead of hidden in a global last-error state.
