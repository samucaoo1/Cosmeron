# Numeric

The **Numeric** module provides additional numeric representations built from C integer and floating-point types: exact rational fractions, complex values, fixed-point values, and fixed-width multi-limb integers/decimal values.

## Headers

~~~c
#include "Cosmeron/Modules/Numeric/Numeric.h"
~~~

The aggregate header includes the Rational, Complex, Fixed, Bigint and Decimal declarations. Individual headers can be included when only one representation is needed.

---

# Overview and available specializations

| Family | Representation | Current built-in specializations |
| --- | --- | --- |
| Rational | Numerator and denominator of one integer type. | `Int32`, `Int64` |
| Complex | Real and imaginary components of one floating-point type. | `Float32`, `Float64`, `Float128` |
| Fixed | Signed raw integer plus a compile-time fractional-bit count. | `Q8_8`, `Q16_16` |
| Bigint | Unsigned fixed-width multi-limb integer. | 128, 256, 512, 1024 bits |
| Decimal | Fixed-width multi-limb value with the same integer-limb arithmetic interface. | 128, 256, 512, 1024 bits |

The suffixes are generated by the tables in `Modules/Numeric/Impl/Common.inc`. Width-suffixed Bigint/Decimal objects store 64-bit limbs; their bit width is fixed by the selected type.

# API reference

## Rational

Header: `Rational.h`. Type: `MODULE_TYPED(Numeric, Rational, Int32)` or `MODULE_TYPED(Numeric, Rational, Int64)`.

A rational is stored as `numerator / denominator`. `Make` rejects a zero denominator, normalizes the denominator sign and reduces the fraction by the greatest common divisor.

| Function | Contract |
| --- | --- |
| `Gcd(a, b)` | Returns the greatest common divisor helper result. |
| `Make(numerator, denominator, outValue)` | Constructs a normalized rational. |
| `Add(a, b, outValue)` | Adds two fractions. |
| `Sub(a, b, outValue)` | Subtracts two fractions. |
| `Mul(a, b, outValue)` | Multiplies two fractions. |
| `Div(a, b, outValue)` | Divides by the second fraction; the second numerator must not be zero. |
| `Compare(a, b)` | Returns `CMPOUT` ordering. |
| `ToFloat64(value)` | Converts the fraction to `double`. |

~~~c
MODULE_TYPED(Numeric, Rational, Int32) third, sixth, half;

OPSTATUS status = MODULE_FUNC(Numeric, Rational, Int32, Make)(1, 3, &third);
if (status == STATUS_CONST(SUCCESS)) {
    status = MODULE_FUNC(Numeric, Rational, Int32, Make)(1, 6, &sixth);
}
if (status == STATUS_CONST(SUCCESS)) {
    status = MODULE_FUNC(Numeric, Rational, Int32, Add)(third, sixth, &half);
}

double result = MODULE_FUNC(Numeric, Rational, Int32, ToFloat64)(half);
~~~

Rational operations use the selected underlying C integer type. They are not arbitrary-precision rational arithmetic; callers must keep intermediate values within the representable range of that type.

## Complex

Header: `Complex.h`. Specializations: `Float32`, `Float64` and `Float128`.

A complex value stores `real` and `imag` fields and represents `real + imag * i`.

| Function | Contract |
| --- | --- |
| `Make(real, imag)` | Constructs a complex value. |
| `Add(a, b)`, `Sub(a, b)`, `Mul(a, b)` | Return the arithmetic result. |
| `Magnitude.Squared(value)` | Returns `real² + imag²`. |
| `Magnitude(value)` | Computes the magnitude. |
| `Div(a, b, outValue)` | Divides into an output value; rejects a zero-magnitude divisor. |
| `Conjugate(value)` | Returns the complex conjugate. |
| `Equals(a, b)` | Tests exact component equality. |

~~~c
MODULE_TYPED(Numeric, Complex, Float64) value =
    MODULE_FUNC(Numeric, Complex, Float64, Make)(3.0, 4.0);

double magnitude =
    MODULE_FUNC(Numeric, Complex, Float64, Magnitude)(value);
~~~

`Equals` compares both components exactly; it is not an epsilon/tolerance comparison. The magnitude implementation is an internal iterative calculation and floating-point edge cases remain subject to normal precision limits.

## Fixed-point

Header: `Fixed.h`. Built-in types: `Q8_8` and `Q16_16`.

A fixed-point value stores one signed raw integer. The suffix encodes the storage and fractional-bit configuration: `Q8_8` uses an 8-bit fractional part and `Q16_16` uses 16 fractional bits.

| Function | Contract |
| --- | --- |
| `From.Raw(raw)` | Constructs directly from the stored raw integer. |
| `From.Int(value)` | Converts an integer to the fixed-point scale. |
| `From.Float64(value)` | Converts a double to the fixed-point scale. |
| `To.Int(value)` | Converts to the integer part. |
| `To.Float64(value)` | Converts to double. |
| `Add(a, b)`, `Sub(a, b)`, `Mul(a, b)` | Return a fixed-point value. |
| `Div(a, b, outValue)` | Divides into an output value; returns an error for a zero divisor. |
| `Compare(a, b)` | Returns `CMPOUT` ordering. |

~~~c
MODULE_TYPED(Numeric, Fixed, Q16_16) a =
    MODULE_FUNC(Numeric, Fixed, Q16_16, From_Float64)(2.5);
MODULE_TYPED(Numeric, Fixed, Q16_16) b =
    MODULE_FUNC(Numeric, Fixed, Q16_16, From_Int)(3);

MODULE_TYPED(Numeric, Fixed, Q16_16) product =
    MODULE_FUNC(Numeric, Fixed, Q16_16, Mul)(a, b);
double converted =
    MODULE_FUNC(Numeric, Fixed, Q16_16, To_Float64)(product);
~~~

Multiplication and conversion use the wider intermediate integer type configured for the specialization. Arithmetic is fixed-width; check your input range rather than assuming saturation.

## Bigint and Decimal

Headers: `Bigint.h` and `Decimal.h`. Standard types: `MODULE_TYPE(Numeric, Bigint128)` through `Bigint1024` and `MODULE_TYPE(Numeric, Decimal128)` through `Decimal1024`.

These are fixed-width objects backed by little-endian arrays of 64-bit limbs. They are not dynamically growing integers. The available method families are:

| Group | Methods |
| --- | --- |
| State | `Clear` |
| Arithmetic | `Add`, `Sub`, `Mul`, `Div`, `Mod`, `Increment`, `Decrement` |
| Division outputs | `Div.Mod(divisor, outQuotient, outRemainder)` |
| Bitwise | `And`, `Or`, `Xor`, `Not` |
| Shifts | `Shift.Left`, `Shift.Right` |
| Rotations | `Rotate.Left`, `Rotate.Right` |
| Individual bits | `Bit.Set`, `Bit.Clear`, `Bit.Check` |
| Comparison | `Compare(other, outResult)`, `Equal`, `NotEqual`, `LessThan`, `GreaterThan`, `LessOrEqual`, `GreaterOrEqual` |
| Formatting | `ToCString.Base(base, buffer, bufferSize)`, `ToCString(buffer, bufferSize)` |
| Query | `IsZero` |

`Compare` writes a `CMPOUT` value through `outResult` and returns `OPSTATUS`; the relational predicates return `bool`. The arithmetic methods mutate the receiver and return `OPSTATUS`. `Div` writes the quotient to the receiver. The `Div.Mod` variant writes quotient and remainder into two distinct output objects without changing the receiver. `Mod` writes the remainder to the receiver. The formatting methods write a null-terminated representation into a caller-owned buffer; check the returned status and capacity.

~~~c
MODULE_TYPE(Numeric, Bigint128) left = {0};
MODULE_TYPE(Numeric, Bigint128) right = {0};

OBJECT_CALL_0(&left, Clear);
OBJECT_CALL_0(&right, Clear);

/* Set the low limb when constructing a small test value. */
left.limb[0] = 40U;
right.limb[0] = 2U;

OPSTATUS status = OBJECT_CALL(&left, Add, &right);
~~~

The limb representation is exposed in the generated type. Directly writing limbs is appropriate for low-level initialization and serialization code, but ordinary arithmetic should use the provided operations so overflow is reported.

# Error and arithmetic behavior

- Fallible operations return `OPSTATUS`. A failed operation may leave the receiver unchanged when the implementation uses a temporary result, but callers should rely on the documented method contract rather than assume transactional behavior everywhere.
- `INVALID_ARGUMENT` is used for invalid pointers and invalid output combinations; a zero divisor is reported as `DIVISION_BY_ZERO`.
- `ARITHMETIC_OVERFLOW` is returned when a fixed-width multi-limb operation cannot represent its result.
- Rational and fixed-point storage is bounded by the underlying C integer types.
- Complex values are floating-point values and can encounter rounding, overflow, underflow and NaN behavior.
- Bigint/Decimal capacity is fixed at the type width; overflow is reported, not expanded into another limb.

## Templates

Rational and Complex specializations are generated from their type tables. Fixed uses a four-field specialization row: suffix, storage type, wider intermediate type and fractional-bit count. Bigint and Decimal use the width table.

The common template engine supports custom instantiation when a module header exposes the matching template definition. Keep the type/table row format consistent with the relevant template's parameters; a width not present in the current built-in table is not automatically provided by the aggregate header.
